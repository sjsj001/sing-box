### 结构

```json
{
  "type": "smart",
  "tag": "smart",

  "outbounds": [
    "hk",
    "de",
    "sg",
    "jp"
  ],

  "probe_interval": "",
  "ping_interval": "",
  "idle_timeout": "",

  "switch_margin": 15,
  "min_dwell": "",
  "tolerance": 20,
  "cdn_threshold": 25,
  "cdn_band": 15,
  "cdn_quorum": 2,

  "queue_delay_threshold": 200,
  "congest_suppress_max": 3,
  "handshake_verdict_timeout": "",

  "nodes": [
    {
      "tag": "jp",
      "clean_priority": 1,
      "bias_ms": 0
    }
  ],
  "regions": [
    {
      "name": "east-asia",
      "members": ["hk", "jp"],
      "mode": "prefer",
      "primary": "hk"
    }
  ],

  "interrupt_exist_connections": false
}
```

!!! warning "前置条件"

    所有成员必须是 `naive` 出站，且每个成员对应的**服务端**必须运行本 fork 中带
    `sbprobe` 分支的 naive 构建。成员不是 naive 时该组拒绝启动；服务端没有探测
    分支时不会响应探测，该组会将其判定为不可用并在日志中说明原因。

    暂不支持 `providers` 与 `use_all_providers`，请显式列出 outbounds。

### 为什么需要它

`urltest` 只为每个节点测一个数——到某个固定测试 URL 的延迟——然后把所有流量都发给
胜出的那个节点。当节点分散在不同地区、目标也分散在不同地区时，这个数就是错的：离
`gstatic.com` 最近的节点，并不是离法兰克福某台服务器最近的节点。

`smart` **按目标主机**分别选路。它把每个请求的延迟拆成两段，分开测量：

* **本地段** —— 你到代理。通过各成员自己的隧道打探测包测得，取 90 秒滑动窗口内的
  最小值，这样瞬时排队（bufferbloat）无法抬高它。
* **远端段** —— 代理到目标。**由服务端测量**：服务端自己发起 TCP 连接并计时，把结果
  回传。所以这个数不受你隧道冷热状态影响，对该节点从未访问过的目标同样有效。

节点得分是 `本地 + 远端`（再加上你的手动偏置），于是法兰克福的目标走德国节点、香港的
目标走香港节点，同时生效，你不需要为其中任何一个写路由规则。

!!! info "没有测速链接"

    从 `urltest` 过来，第一反应是找 `url` 字段。这里没有这个字段，也没有任何"测速链接"
    可以改。

    本地段根本不接触外部目标：它通过成员自己的隧道向你的代理服务端打一个标记包，服务端
    直接应答，因此这个数始终只衡量*你到代理*这一段。远端段则是针对**你实际要连的目标**、
    在**你实际使用的端口**上测量的——你连 `1.1.1.1:80`，就会给每个成员计时"连到
    `1.1.1.1:80` 要多久"。

    每个目标都是它自己的测速目标，这正是关键所在：任何一条固定的测速链接，都只可能对
    离它近的目标是正确的。

### 行为

#### 按主机，而非按域名

分桶键是**主机名**，不是注册域名。同一域名下按地区分布的服务商——比如
`example.net` 下同时有法兰克福和新加坡的机器——每个主机名各自决策。无域名的目标
（IP 字面量）按地址分桶。

#### 第一个请求就是最优的

某个主机首次出现时，该组会先从所有可用成员探测远端段，再做决定。这会让那**一个**请求
多花约半秒，换来的是不存在"先连上再纠正"的阶段。

只有 UDP 流量的主机（STUN、WebRTC）没有可探测的 TCP 端口，会跳过这一步，改用稳定的
区域选择。

#### 粘滞，且有迟滞

主机一旦选定节点就保持不变。挑战者必须以 `switch_margin` 百分比胜出（下限为
`tolerance` 毫秒）、**连续两轮测量**都赢、并且熬过 `min_dwell`，才会真的切换。"两轮"
指的是两次独立的测量——拿同一批样本重新判一次不算第二次胜出。

例外是那些在测量不完整的情况下做出的选择——回退选择，或者测量时某个成员不可达。这类
选择允许被立即纠正一次，好让早期的猜测不必等满整个窗口。

切换属于延迟优化而非故障转移，因此不会打断已经建立的连接。

#### CDN 目标的选法不同

当多个成员对某主机测出的远端延迟都很低时，说明它是 anycast 或 CDN——每个节点都"很近"，
延迟已经失去区分度。对这类目标，该组不再按快慢排序，而是在距最快节点 `cdn_band` 以内
的成员中挑**最干净**的那个（见 `clean_priority`）。这正是让 CDN 流量走你风控最轻的出口、
同时不影响其他任何目标的机制。

#### 故障处理

三个相互独立的层次，每层都刻意做了阻尼，使单个突发事件不会搬动本不需要搬动的流量：

* **按目标。** 某成员对某主机失败时，只封锁**这一对**——30 秒，重复则 2 分钟、10 分钟。
  一次成功的探测会提前解封并回退升级等级，因此恢复了的路径会直接回到最短间隔。一个挂掉
  的目标永远不会赔上整个节点。
* **按成员。** 只有在证据持续时才判定成员死亡：连续两次硬错误，或活动连接在一分钟内对
  **两个不同**主机失败（单个挂掉的目标只会重复同一个主机名，因此永远触发不了这条）。
  恢复需要连续多次干净探测，反复抖动的成员每次需要保持干净的时间更长。
* **拥塞还是死亡。** 探测超时本身是有歧义的——可能是你自己的上行被打满。在归咎于成员
  之前，该组会找一个*见证者*：另一个探测返回了、但比自身基线膨胀超过
  `queue_delay_threshold` 的成员。有见证者说明问题在本地，该成员可获得最多
  `congest_suppress_max` 轮宽限。没有见证者时，由一次在全新会话上的宽松握手做终审。

节点突然死亡的代价约为一个失败请求：该连接的首个硬错误立即为这个主机改道，不必等到下
一次探测。

### 字段

#### outbounds

==必填==

参与选路的 `naive` 出站标签列表。

#### probe_interval

每个活跃目标的远端段多久重测一次。默认使用 `45s`。

这是该组的时钟：一个样本在两个间隔内视为新鲜，"连续两轮胜出"也是按轮计数。单轮时长由
构造保证不超过一个间隔——目标按最近使用优先刷新，间隔用尽即停止派发，把冷门的尾部推到
下一轮，而不是让本轮拖长。

#### ping_interval

每个成员的本地段多久测一次，同时也是健康检查的节奏。默认使用 `5s`。

#### idle_timeout

某目标在最后一次使用后，其学习状态保留多久。默认使用 `30m`。

#### switch_margin

挑战者需要好出多少（百分比）才能取代粘滞节点。默认使用 `15`。该余量以在位节点自身的
得分为基准计算，并以 `tolerance` 为下限，使得分接近零时仍需要真实差距。

#### min_dwell

主机在某节点上至少停留多久才允许被搬走。默认使用 `30s`。

#### tolerance

两个总分在多少毫秒内视为相等。默认使用 `20`。

在这个带宽内，该组优先选**远端段**更低的节点。这条规则让平局倒向真正离目标更近的节点，
而不是碰巧到你这里链路更快的那个。

#### cdn_threshold

远端延迟低于多少毫秒时，该成员在 CDN 判定中算作"离目标很近"。默认使用 `25`；退出该
分类需要再高 10ms，因此处于边界的主机不会来回翻转。

#### cdn_band

对被判定为 CDN 的目标，其他成员的远端延迟最多可比最快成员高出多少毫秒仍被纳入考虑，
单位毫秒。默认使用 `15`。在这个带宽内由最干净的节点胜出。

#### cdn_quorum

需要多少个成员低于 `cdn_threshold`，才把该目标判定为 CDN。默认使用 `2`。

#### queue_delay_threshold

成员的探测延迟需要比自身滑动最小值基线高出多少毫秒才算"膨胀"。默认使用 `200`。

这一个阈值承担两项职责。当某成员膨胀*而另一成员没有*时，说明它的本地段劣化，会按实测
膨胀量在排序中受罚直到恢复——流量立刻迁走，而不必等约 90 秒让它的基线追上来。而当某成员
膨胀*而另一成员超时*时，它就是证明该超时属于本地拥塞而非死亡的见证者。

#### congest_suppress_max

有见证者证明是本地拥塞时，超时的成员最多可以被宽恕多少个连续轮次。默认使用 `3`。超过
之后仍要面对握手终审——否则一个真正死掉的成员就能长期躲在拥塞的上行后面。

#### handshake_verdict_timeout

终审的超时：向该成员建立一个全新的 TLS 会话，走独立的连接池。默认使用 `8s`。

它刻意设得很宽松。走到这一步说明歧义已经收敛到"慢还是死"，而误判为"死"的代价远高于多等
一会儿。

#### nodes

按成员的调优。未列出的成员使用默认值。

#### nodes.tag

成员的出站标签。

#### nodes.clean_priority

序数，**越小越干净**。默认使用 `100`，因此你没有标注的成员排在任何标注过的成员之后。

这是"这个出口最不容易让我撞验证码"的旋钮。它**只**在被判定为 CDN 的目标上生效——那时
延迟已经失去区分度；它绝不会覆盖普通目标上真实存在的延迟差距。

#### nodes.bias_ms

加到该成员得分上的手动偏移，单位毫秒。负值意味着偏好该成员。会被钳制到 ±100 并给出警告，
以免手误的数值悄悄劫持所有决策。

#### regions

把处于同一地点的成员归组。

#### regions.name

区域名称。

#### regions.members

该区域内的成员标签。

#### regions.mode

`prefer` 只在主节点不可用时才启用该区域的备用节点；`equivalent` 视成员为可互换，交由
测量决定。默认使用 `equivalent`。

#### regions.primary

`prefer` 模式下的首选成员。

#### interrupt_exist_connections

当某成员被判定死亡时，中断它已有的连接。

仅入站连接受此设置影响，内部连接将始终被中断。

该设置**只作用于死亡**。目标迁移到更快的节点时，永远不会中断任何连接。

### 可观测性

该组每分钟以 `info` 输出一行固定长度的成员健康信息，并在每次目标更换节点时输出一行：

```
smart nodes: hk[health=0 local=27ms] de[health=0 local=164ms] sg[health=0 local=64ms]
smart: example.com switched de -> hk by=total
```

`by=` 指明是哪个维度决定的：`total`（本地+远端最低）、`remote`（总分在 `tolerance` 内，
于是更近的节点胜出）、`cdn`（判定为 CDN，于是最干净的节点胜出）。

`debug` 级别下还会输出每轮刷新的目标数量与实际耗时。新部署时值得看一眼：本组所有抗抖
阈值都以"轮"计价，如果实际轮次时长明显偏离 `probe_interval`，那么这些参数的含义就不
再成立。

!!! note

    按目标的切换日志包含主机名。如果你不希望浏览记录进入日志，请将日志级别设为 `warn`。
