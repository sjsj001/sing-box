### 结构

```json
{
  "type": "failover",
  "tag": "HK",

  "outbounds": [
    "hk-a",
    "hk-b"
  ],
  "strategy": "order",
  "health_check": "1.1.1.1:80",
  "cooldown": {
    "fail_limit": 2,
    "base": "1m",
    "max": "15m"
  },
  "hedge_delay": "",
  "interrupt_exist_connections": false
}
```

### 工作原理

failover 组让所有连接走一个首选成员，其余成员作为待命 —— 当首选成员
故障时接管，故障有两种粒度：**针对单个目标**（该成员的出口访问不了某个
网站）或**整体故障**。它不做延迟学习、不做按目标择优：面向的是同区域
可互换的节点。跨区域按站点选路请用 [Smart](/zh/configuration/outbound/smart)
组 —— 两者天然组合：failover 组作为 smart 的成员。

故障处理分三层，从快到慢：

1. **同调用重试**：拨号失败在同一连接内顺延下一成员 —— 用户无感知。
   每次尝试有自适应预算（`max(3 × 成员基线, 1s)`，上限 5s），挂死的
   成员吃不掉调用方的整个超时。
2. **对冲请求**（可选，见 `hedge_delay`）：主成员接受了连接但迟迟没有
   响应字节时，把同样的请求并发发给待命成员，首个响应字节获胜。
3. **按目标冷却**：连续 `fail_limit` 次失败（拨号错误、早期重置、或
   3 秒内零字节挂起）将该成员**仅对该目标**排除，复发指数退避，且需
   针对该目标的验证探测通过才恢复。

成员级健康每分钟对 `health_check` 探测一次：连续 3 败整体摘除（可选
中断其存量连接），2 成恢复。某目标下*全部*成员都被排除时，按偏好顺序
放行（fail-open）而不是拒绝服务。

状态只存内存：冷却是分钟级瞬态，没有值得跨重启保留的东西。

### 字段

#### outbounds

==必填==

有序的成员出站标签。`strategy: order` 下即偏好顺序；`strategy: auto`
下作为破平顺序。

#### strategy

全员健康时如何选主：

| 值 | 含义 |
|----|------|
| `order`（默认） | 严格取 `outbounds` 中第一个健康成员 —— 适合你明确知道谁该承载流量 |
| `auto` | 健康检查基线（滚动最小值）最低者当选 —— 适合你不关心、让系统来挑 |

`auto` 下换主需要挑战者基线连续 3 轮（约 3 分钟）低于现任 20% 以上 ——
基线接近的节点之间不会来回跳。现任死亡则立即换主。换主只影响新连接。

#### health_check

每分钟经每个成员探测一次的 `host:port`，用于成员存活（3 败下线 / 2 成
恢复）以及 `strategy: auto` 的选主基线。默认 `1.1.1.1:80`。

#### cooldown

按目标排除，与 smart 组同构：连续 `fail_limit` 次失败将该成员对该目标
冷却 `base`，快速复发时翻倍、上限 `max`；恢复需针对该目标的验证探测
通过。收到响应字节即清零失败计数 —— 多路复用协议"拨号永远成功"的
特性已被正确处理。

| 字段 | 默认 |
|------|------|
| `fail_limit` | `2` |
| `base` | `1m` |
| `max` | `15m` |

#### hedge_delay

设置后启用对冲请求（如 `"1.5s"`）；留空关闭。

主成员在该时限内没有产生响应字节时，把已缓冲的客户端字节重放给下一个
合格成员，首个响应字节获胜；败者被关闭且**不计惩罚**（慢不等于坏 ——
只有真实错误计入冷却）。主成员直接失败时对冲立即启动、不等时限。由此
即使路径被静默丢包，用户感知延迟也被封顶在约 `hedge_delay + 待命成员
RTT`。

代价：慢于时限的请求短暂占用两条上游连接。仅 TCP；UDP 对冲会把数据报
复制到两个上游，对 QUIC 这类面向连接的协议行为不可预测。扇出为 1
（主 + 一个待命）。

#### interrupt_exist_connections

成员被健康检查摘除时中断其存量连接，使其经健康成员重拨，而不是挂在
死路径上。

仅入站连接受此设置影响，内部连接将始终被中断。
